1. Executive Summary & Objective

In modern machine learning engineering, accurately identifying the appropriate learning paradigm (Supervised Learning, Unsupervised Learning, or Reinforcement Learning) for an ambiguous business or industrial problem is the foundational step before architectural design or data collection. Misclassifying an active sequential decision problem as static supervised regression, or attempting supervised modeling on unlabelled anomaly telemetry, leads to severe project failure.

This project implements an intelligent, real-time classifier system that:

  • Accepts natural language problem descriptions from arbitrary industrial domains.
  • Executes Chain-of-Thought (CoT) step-by-step decision tree reasoning via Groq (powered by openai/gpt-oss-120b / qwen/qwen3.8-27b).
  • Generates calibrated epistemic confidence vectors satisfying \(p_{\text{supervised}} + p_{\text{unsupervised}} + p_{\text{reinforcement}} = 1.0\) and recommends appropriate ML algorithms.
  • Generates a balanced corpus of 200 diverse domain scenarios (U2).
  • Fine-tunes a lightweight DistilBERT model in TensorFlow / Keras on synthetic data (U3 & U4).
  • Validates performance on an independent benchmark of 20 hand-labelled edge cases across Healthcare, Finance, Retail, and Manufacturing (U5).
  • Deploys an interactive web dashboard on Streamlit Community Cloud.

3. U1: Chain-of-Thought Classifier & Confidence Mechanism

3.1 Structured Decision Hierarchy

The Chain-of-Thought prompting protocol enforces sequential evaluation through a strict hierarchical decision logic:

  1. Reinforcement Learning Test: Does an autonomous agent observe environmental states, take sequential actions, and receive scalar feedback (rewards or penalties) over time? If yes → reinforcement.
  2. Supervised Learning Test: Is there an explicit ground-truth target variable (continuous or categorical) associated with each historical observation that the model must predict? If yes → supervised.
  3. Unsupervised Learning Test: Is the primary objective to uncover latent clusters, manifolds, or statistical anomalies without target labels? If yes → unsupervised.

3.2 Groq Confidence Calibration vs. Token Logprobs

The standard OpenAI API exposes token logprobs via logprobs=True. However, the Groq Chat Completion API does not support token logprob parameters (requesting them returns an HTTP 400 Bad Request).

To solve this, our system implements an explicit probability vector output requirement (CONFIDENCE: {"supervised": 0.xx, "unsupervised": 0.xx, "reinforcement": 0.xx}). The reasoning engine validates the vector, normalizes the values so that \(\sum_{i} p_i = 1.0\), and updates the Streamlit visualization bar charts.

4. U2: Synthetic Data Generation

To train the distilled model without requiring expensive human annotation, a balanced dataset generator was constructed (src/generate_data.py). It synthesized 200 distinct scenarios across 3 paradigms and 5 industrial domains:

  • Finance: Credit card default scoring, SWIFT graph anomaly detection, high-frequency limit order routing.
  • Retail: Grocery SKU sales forecasting, latent product basket association, dynamic repricing.
  • Manufacturing: Bearing remaining useful life (RUL), wind turbine acoustic anomaly detection, chemical reactor valve policy control.
  • Education: Course dropout risk modeling, AST syntax clustering, adaptive tutoring problem sequencing.

7. Critical Limitations, Domain Bias & Edge Cases

  1. Boundary Blurring (Static Prediction vs. Dynamic Policy): Problems such as retail dynamic pricing or high-frequency trading can be formulated either as supervised demand estimation (predicting next period volume) or reinforcement learning (executing price actions that actively alter market demand).
  2. LLM Synthetic Data Artifacts: Synthetic training data generated by LLMs tends to use explicit indicator terms (e.g., "unlabelled", "rewards", "ground truth labels"), whereas real-world enterprise problem specifications are ambiguous and informally defined.
  3. Statistical Power of Small Test Benchmarks (\(N=20\)): While hand-labeling 20 detailed scenarios ensures qualitative validity, a sample size of 5 per domain means each single error results in a 20% domain accuracy swing.
